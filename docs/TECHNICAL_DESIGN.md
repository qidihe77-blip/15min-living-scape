# 技术设计

核对日期：2026-10-16。生产分类 `facility-categories-v8` / `six-group-public-services-v8.6`。本次交付不改变核心计算或UI设计。

## 1. 架构与任务流

浏览器原生ES Modules、BMapGL、ECharts及MapVGL；后端为Node.js标准库HTTP服务，无数据库与框架依赖。`server/index.mjs` 创建服务，`web/display-shell.html` 缩放业务iframe，`web/console.js` 组织地图与报告。任务创建后以ID轮询进度。

```mermaid
flowchart LR
 U[地点与优先级] --> J[任务管理器]
 J --> P[Place分页检索]
 J --> R[36方向Walking采样]
 P --> C[去重与规则分类]
 C --> W[缓存与真实Walking]
 W --> A[可选方向补点]
 R --> A
 W --> S[18小类覆盖评分]
 A --> D[同源展示快照]
 S --> D
 D --> M[地图路线与报告]
 D --> G[六大类200m盲区]
```

完整结果保存审计证据；`ui-snapshot.mjs` 精简重复字段，同时保留起终点绑定、路径、评分指纹及盲区证据。归档按SHA-256核验后只读恢复；展示快照不能替代完整证据进行在线重算。

## 2. Walking口径与36方向边界

全链路采用 **BD-09LL**。模型时间为 `distanceMeters / 80 × 60` 秒，15分钟包含等号，即 **≤1200m**。百度原始duration另行保留。路线须绑定当前起点、设施UID或确认入口及坐标；Point-in-Polygon不决定可达性或计分。

`isochrone-algorithms.mjs` 仅注册 `walking36`。`centered-walking-range.mjs` 在36个10°方向上，从 `[0,2340m]` 径向窗口进行三轮二分，满额108个真实RouteMatrix OD。各方向用最后有效观测构建有界比例径向成本模型，求1200m成本半径，按角度直接闭合为37顶点基础折线。**两条范围均无Catmull-Rom平滑**。1公里圈用相同起点、方向和径向模型求1000m半径，不是直线Buffer。

矩阵不可用时回退原单条Walking径向采样。部分缺失方向在满足有效样本门槛时用中位半径补齐并标记estimated；不足或几何异常时为明确参考降级形状，不作为可达性、热力或盲区证据。边界是有限采样加成本比例估计，不是精确连续路网等时面。

### 少量自适应补点

`adaptive-directions.mjs` 读取已保存且起终点绑定正确的圈外≤1200m POI，按原10°区间分组、180m空间聚集排序，选取聚集方位中位数并约束在间隔内1°–9°。默认最多6个方向、每方向三次真实测量、18 OD预算；不会直接使用POI作为边界点。

保护条件包括闭合、自交、起点包含、1km圈嵌套、已知超距设施误包和可达设施丢包。新增半径不得超过相邻最大半径250m或1260m，面积增长≤12%、缩减≤2%，且已知漏包应减少，否则回退原36方向。指标只针对已观测设施，不能冒充独立全域精度。`ADAPTIVE_DIRECTIONS_ENABLED=false` 独立回退。

## 3. POI检索与分类

调用 `/place/v3/around`，默认分析直线检索窗口1500m。六类分组召回，每包最多10个 `$` 联合词、每页20条；继续分页、密集分片受请求预算约束。V8大类上限16请求，任务默认60，完整即停止。完整性依据报告总数、唯一POI、页序、终止证据及错误/截断，不能累计重复行数冒充完成。

分类定义见 [V8配置](../data/facility-categories-v8.json)：教育3、医疗3、商业4、交通2、养老3、休闲3，共18小类。规则结合名称、百度tag和可靠详情；召回命中不是分类确认。道路、地址或分店括号中“体育场”等词不成为场馆依据，地铁附属商铺不自动成为地铁站。UID优先去重，地铁出入口依据可靠站点关系归并，保留入口与来源证据。

养老扩展召回护理院、颐养院、长者照护之家等。先确认养老属性，再分类；当前产品将确认养老但小类不明确的设施统一归入养老院，这是分类兜底约定，并非法定机构类型证明。明确日间照料、老年活动中心保持原归属；餐饮、普通商业或纯住宅误命中继续排除。

外围设施保留作空间诊断。检索、分类或路径失败不计入确认可达数。完整表见 [检索说明](POI_RETRIEVAL_AND_CLASSIFICATION.md)。

## 4. API、调度与缓存

径向成本使用 `/routematrix/v2/walking`，POI真实路径使用 `/direction/v2/walking`，成本矩阵不能充当polyline。路线选中时可按需请求 `/directionlite/v1/walking`、`steps_info=1`，只解析明确的人行横道、天桥和地下通道；不推测红绿灯，缺步骤保持空，不参与评分与时间计算。

OD缓存键包含BD-09六位坐标、方向、UID/坐标导航策略和API家族；成本与真实路径分离，相同在途请求复用Promise。成功结果持久化于 `data/runtime/`，默认TTL24h，可设5分钟–7天，最多20000条；失败不伪装成功缓存。

默认单条Walking并发10、起始间隔110ms；Place并发6、105ms；矩阵另按输出OD限流，默认10 OD/s、10000 OD/日，须显式启用并配置真实授权有效期。本地配置上限不代表账户已获额度。

完整设施路径模式按有效端点分配路径及一次重试预算，受1000端点上限约束；初始任务220 OD并非所有模式的绝对总额。关闭完整路径模式恢复固定预算；设0仍禁用。分别记录OD数、HTTP数、限流等待、缓存与耗时。

优化包括径向分组流水、检索预取、同源gzip、静态ETag/gzip、版本固定资源和地图样式代理缓存。`WALKING_ACCELERATION_ENABLED=false` 回退调度。历史性能记录不是今日冷启动成绩，见验证入口。

## 5. 综合评分

设大类小类数nᵢ、确认Walking≤1200m的小类数kᵢ、P1/P2/P3权重pᵢ=3/2/1：

```text
Gᵢ = 100 × kᵢ/nᵢ
wᵢ = pᵢ/Σpᵢ
S_low = Σ(wᵢ × Gᵢ)
```

页面展示S_low；后端保留未确认小类可能贡献的S_high审计上界。相同小类多个设施不重复加分。数量、盲区面积和重点设施1km状态不直接加入综合评分；地图筛选不改分母。

设施可跨大类，六类数之和可能超过UID去重总数；旭日图按唯一归属分配，仍为6类内环、18小类外环。菜市场/药店/小学独立按≤1000m判断；≤1200m有效补充设施才可显示为15分钟最近路线。

## 6. 六大类服务盲区

`blindspot-model.js` 仅生成6个模型。整类确认15分钟可达设施数为0才有资格；部分小类缺失不触发。三个重点设施不参与空间盲区。

`service-gap-grid200-v2` 在有效15分钟折线域内建立200m网格，结合检索支撑窗口、完整性、潜在设施与起点Walking证据，按1000m几何服务半径识别缺失。完整网格须满足边界安全距离，四邻接聚合；25m距离场采样经Marching Squares、20m向内等值、60m尺度平整（最大向内50m）和≤10m局部修整，校验不超确认网格。

**没有逐网格Walking观测**；这是起点可达集合与几何服务距离共同约束的空间诊断，不能当作所有居民位置的精确路网覆盖。证据不足不直接生成确认缺失。

灰色联合面只填一次。默认总外边界，悬停高亮当前位置命中大类各自边界、只显示类别。轮廓平面分段积分得到互斥类型组合面积，重叠只统计一次。卡片百分比分母为**可判定域**，完整等时圈面积单独展示；二者可能不同。卡片只有绿色无盲区或有盲区百分比，无法计算则不展示，不能伪造全覆盖。

## 7. 交互与兼容模块

六类筛选、左侧专项全量、右侧最近聚焦独立控制状态，共用POI Marker和保存路线。教育/医疗/商业展示对应重点服务全量有效路径；右侧再次点击取消最近聚焦。同类重点路线1km内外颜色一致，保留柔光、白描边及流光。POI为紧凑两行卡片并避让。盲区只有总图例显隐，条形图和重点卡不触发盲区。

当前首页不展示天气、生鲜替代或报告导出。旧HTML报告渲染器及兼容测试保留供追溯，没有正式PDF导出HTTP路由，不属于当前功能。接口见 [API文档](API.md)。

## 8. 局限与验证边界

有限采样仍会漏包/误包，补点只改善已有证据的局部。固定80m/min不含个体步速、信号等待和障碍惩罚。缺失只限声明检索范围和当前数据，不证明现实永远不存在设施。服务盲区不是逐网格路网求解。

三地测试使用历史真实采样及标明的当前规则离线回放，杭州为历史参考定位点。通过的测试仅证明列明场景；不能证明API数据完整或全部操作序列均无问题。详见 [三地验证](validation/README.md)。

# A82：Walking调度、地图启动与三入口交互

日期：2026-10-16。后续A83已按最新要求将盲区收敛为六大类；本记录中的专项路线交互仍保留。

## 36方向计算瓶颈与改动

矩阵采样原先要求36方向全部完成一轮，才能开始下一轮。不同批次延迟不一致时，已完成方向仍等待其他方向；与POI算路共享单条请求队列时还会等待排在前面的POI任务。

现将方向分为独立小组，各方向仍执行相同的三轮二分。先完成的小组可进入下一轮；已排队的路网采样优先于尚未开始的POI请求。既有并发、OD级QPS、缓存、每日额度及重试约束不变。整轮没有有效证据时停止，失败绑定与回退仍受保护。`WALKING_ACCELERATION_ENABLED=false`恢复原逐轮等待与FIFO队列。

使用武汉已保存的108份真实矩阵成本离线重放，36方向边界及径向估计完全相同，新增API调用为0。固定70/3ms响应延迟的调度实验为267.8ms→200.3ms；这是隔离调度的受控实验，不是百度实际冷请求提速比例。缓存重放6.1ms→2.7ms也受到JIT与单次运行影响，不作为实际接口性能承诺。此前记录的72.4ms路网阶段已命中108份成本缓存，不能当作冷启动。详见[sampling.json](a82-sampling.json)。

复现：`node scripts/profile-a82-sampling.mjs [完整分析JSON路径]`。默认读取本机`tmp/a81/after/fresh-job.json`；没有原始数据时会失败，不插值伪造样本。回归测试覆盖36/48方向相同输出、部分失败、全轮失败、队列优先级及限流参数。

## 自定义地图加载

已有地图样式JSON约2.49MB，服务端压缩及缓存已存在。主要等待仍在外部SDK、着色器、地图瓦片与主线程/GPU。原HTML提前加载了三个不带版本的着色器URL，SDK实际请求携带版本号，不能可靠复用。

移除不匹配预加载；首访仅观察SDK已完成的公开资源URL，后续访问按24小时TTL提前加载完全相同的原生URL。仅接受固定域名的三个公开脚本及udt/v版本字段，不保存AK、不改写SDK代码。地图设施投影和分类结果按分析、分类表及筛选条件缓存；图表和热力等较重任务优先在首幅地图显示后执行。地图错误时仍释放报告队列。

曾验证本地代理缓存三个SDK脚本：单个资源变快，但整体地图更慢，故已撤销该方案。`map-cache-ab.json`保留此失败实验，不能据此宣称提速，生产没有代理接口或SDK原型修改。

最终原生URL方案在A83只读浏览器回归中，首访38.34秒、同浏览器重复访问6.31秒；第二次学习到3条精确版本预加载，没有额外未版本化资源。首次加载包含网络波动和软件渲染，不能将两次差值归因于本次代码或保证固定提速百分比。最终证据见[当前浏览器记录](a83-browser.json)。此前`map-before.json`、`map-after.json`使用Playwright拦截，HTTP缓存条件不同，仅用于诊断。
